# Публикация Markdown в корпоративный Confluence

Публикует набор `*.md` как страницы Confluence на сервере https://itpm-wiki.mos.ru
через CLI `md2conf`. Markdown — источник истины; конвертация в Storage Format
происходит автоматически, картинки загружаются вложениями, ссылки между файлами
превращаются в ссылки Confluence.

## Расположение рабочего проекта

Все настройки и скрипты готовы в проекте `D:\_DIT\_dit_git_repos\mos_itsm_confl_page_creator`:

| Путь | Назначение |
|---|---|
| `script/publish.sh` | Публикация (настройки сервера зашиты) |
| `script/local-check.sh` | Локальная проверка конвертации, сервер не трогает |
| `script/find-page.sh` | Поиск страниц/пространств по названию |
| `script/venv/` | Python-окружение с `markdown-to-confluence==0.6.1` |
| `.env` | Токен `CONFLUENCE_API_KEY` (значение агенту не раскрывать) |
| `pages/` | Каталог по умолчанию с `*.md` |
| `output/` | Журналы публикаций |
| `manifesto/README.md` | Полное описание проекта |
| `references/server-setup.md` | Настройки сервера (внутри проекта) |

**Не дублируй скрипты** — вызывай готовые. Не создавай новые скрипты публикации,
если задача решается существующими. Скрипты запускаются из любой папки:
`bash "D:/_DIT/_dit_git_repos/mos_itsm_confl_page_creator/script/<скрипт>" ...`

## Проверки перед началом

1. Сервер доступен только внутри сети mos.ru; снаружи curl не ответит — это норма.
2. Токен: проверяется только факт `CONFLUENCE_API_KEY` в `.env`
   (`grep -c CONFLUENCE_API_KEY`), значение не печатать, не логировать, не
   передавать в аргументах команд.
3. Если проект или venv отсутствует — см. установку в `manifesto/README.md` проекта.

## Порядок публикации (обязателен)

1. **Определи источник**: пользователь даёт каталог или файлы `*.md`
   (по умолчанию — `pages/` проекта). Если файлов нет — попросить, не выдумывать.
2. **Локальная проверка** (всегда первой, без исключений):
   ```bash
   bash "D:/_DIT/_dit_git_repos/mos_itsm_confl_page_creator/script/local-check.sh" <каталог-или-файл>
   ```
   Покажи пользователю, во что превратятся страницы (.csf-файлы), отметь
   картинки и возможные проблемы (неизвестные макросы, mailto-ссылки).
3. **Родительская страница — спрашивать каждый раз** (правило пользователя).
   Варианты: корень пространства, конкретная страница (название или ссылка).
   Для поиска родителя: `bash ".../find-page.sh" "название"`; из ссылки можно
   взять номер страницы. Номер — обязательный аргумент `--root-page` при
   публикации под страницу. Стандартный родитель пользователя (когда назовёт):
   пока не зафиксирован.
4. **План изменений**: перечисли, какие страницы будут созданы/обновлены, и
   жди явного согласия на публикацию. Публикация без явного «да» запрещена.
5. **Публикация**:
   ```bash
   bash "D:/_DIT/_dit_git_repos/mos_itsm_confl_page_creator/script/publish.sh" <каталог-или-файл> [--root-page ID]
   ```
   Флаги уже внутри: `--api-version v1 --path / --no-overwrite --webui-links
   --no-notify --no-generated-by --space 4ME`. Журнал пишется в `output/`.
6. **Проверка результата**: нулевой код выхода — необходимое, но недостаточное
   условие. Предложи пользователю проверить в браузере:
   https://itpm-wiki.mos.ru/spaces/4ME (рендер, иерархию, картинки, ссылки).

## Правила безопасности (нарушать нельзя)

- **Не переопубликовывать страницы с ручным контентом**: md2conf регенерирует
  тело страницы целиком. Страницы, которые вели вручную или с макросами,
  не подключать к markdown-синхронизации без явного решения пользователя.
- **Метаданные заменяют, а не добавляют**: если в *.md есть `tags` — все не
  перечисленные метки будут удалены; `properties` аналогично. Не добавлять
  `tags`/`properties` в шапки файлов без явной просьбы пользователя.
- **Вложения**: синхронизация удаляет со страницы картинки, не упомянутые в
  `*.md`. Если у пользователя нет прав на удаление вложений, добавь флаг
  `--attachment-sync upsert` (есть в md2conf 0.6.1).
- **mailto-ссылки** превращаются в упоминания пользователей и могут уведомить
  человека при первой публикации. Такие ссылки находить на этапе локальной
  проверки и спрашивать пользователя.
- **`--no-overwrite`** защищает только страницы, синхронизированные md2conf
  ранее. На новые названия он не влияет: если страница с таким названием уже
  существует и ведётся вручную — сначала спросить пользователя.
- Ничего не удалять (ни страницы, ни файлы, ни вложения) без явного согласия.

## Другие пространства

Скрипты зашиты на пространство `4ME`. Для другого пространства: запускай
`md2conf` напрямую из `script/venv/Scripts/md2conf` с нужным `--space KEY`
(список пространств: `find-page.sh --spaces`), сохраняя остальные флаги из
`publish.sh`. При регулярной работе с новым пространством — добавь отдельный
скрипт в `script/`, не меняя publish.sh.

## Отладка (известные ловушки)

- `Confluence base path must start and end with a '/'` — Git Bash превращает
  `/` в путь Windows. Скрипты уже содержат `MSYS_NO_PATHCONV=1`; если запускаешь
  md2conf напрямую — экспортируй эту переменную.
- `WinError 3 ... '\d\_Prj\...'` — Python не понимает пути `/d/...`; переводи
  через `cygpath -w`.
- Русские буквы в CQL-запросах через curl портятся (CP1251 вместо UTF-8) —
  `find-page.sh` уже использует Python-кодирование; новые поисковые скрипты
  делай на Python/urllib, не на curl с кириллицей.
- `401` от сервера — токен протух: попроси пользователя обновить `.env`.

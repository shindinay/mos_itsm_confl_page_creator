О расширении

Расширение предназначено для сбора списка лиц, которым предоставляется доступ к демо-стенду, при регистрации запроса по шаблону «МосИТСМ. Предоставление доступа к демо стенду» (категория request_template, вкладка «Информация»).

Использование

Пользователь заполняет единственное видимое поле вкладки «Список лиц»: добавляет в него людей по одному из представления «лица_без_локальных» (мультивыбор, до 100 записей, кнопка добавления подписана «Добавить»). Подсказки при выборе показывают заголовок «Лица». Дополнительно заполнять нечего: остальная разметка вкладки — служебные и скрытые поля.

Особенности

Вкладка состоит из трёх секций. Заполнению доступна только первая секция с полем «Список лиц»; вторая секция скрыта классом hide с атрибутом data-internal (style="display:none") и размещает служебное текстовое поле «Запрос в р-сервис» (request_rservice); третья секция скрыта классом hide с атрибутом data-hidden и содержит контейнер расширенного текста note_rservice (класс rich-text, скрыт) для служебной заметки. JavaScript- и CSS-вкладки отсутствуют: динамическая логика не выполняется, видимость задана статически классами в разметке, стили платформы не переопределяются. Обязательность поля «Список лиц» обеспечивается классом required. Поле «Запрос в р-сервис» имеет класс show-when-empty — служебное поле внутренней интеграции, платформа показывает его только когда значение пусто. Активная версия 8 (id 174007); подготовлена версия 9 (id 210117), не активирована.

Элементы управления (кнопки и динамическое поведение)

Кнопки платформенных действий в разметке нет; у поля «Список лиц» кнопка добавления записи подписана «Добавить» (data-custom-link-items-label). JavaScript- и CSS-вкладки отсутствуют: обработчики событий, хуки платформы (в том числе after-prefill) и обращение к данным записи не используются; после открытия вкладки состояние формы не меняется. Видимость секций задана статическими классами в HTML-вкладке: видима только секция «Список лиц», служебные секции скрыты постоянно. Атрибут data-internal скрывает секцию «Запрос в р-сервис» от обычных пользователей (внутреннее поле ДИТ); класс show-when-empty показывает это поле только при пустом значении.

8.1.2. Требования к правилам автоматизации

3 правила автоматизации на шаблоне запроса:

  • ID 10249331: Закрыть запрос если переоткрыли — Правило автоматизации служит защитой от повторного открытия (переоткрытия) автоматически выполненного запроса. Если закрытый запрос снова переводят в работу, правило немедленно возвращает запрос в статус «Завершено» с прежними участником и причиной завершения и оставляет заявителю пояснение: запрос https://itsm.itsm-qa.mos.ru/automation_rules/10249331
  • ID 10249443: Создать запрос в Р-Сервис. Заказ демо-стенда (ApiGate 1.0) — Правило автоматизации передаёт запрос в систему вендора через интеграцию ApiGate 1.0. Когда запрос входит в статус «В рабочем процессе» (ожидание исполнения РП), правило собирает данные заявки (номер, список лиц, тему, описания, контактные данные, вложения и последний открытый комментарий) и вызывае https://itsm.itsm-qa.mos.ru/automation_rules/10249443
  • ID 13553013: Завершить после решения от р-сервис — Правило автоматизации завершает запрос после получения решения от вендора (р-сервис). Интеграция записывает результат в служебные поля расширения UI: note_rservice (заметка от вендора) и request_rservice (номер запроса вендора). Когда поле note_rservice обновляется при непустых обоих служебных полях https://itsm.itsm-qa.mos.ru/automation_rules/13553013

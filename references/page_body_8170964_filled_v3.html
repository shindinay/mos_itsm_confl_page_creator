8.1.1. Требования к Расширению UI

Расширение UI 14567 «Предоставление демо стенда» (активная версия 174007) предназначено для сбора списка лиц, которым предоставляется доступ к демо-стенду при регистрации запроса по шаблону. Вкладка «Информация» содержит одно заполняемое поле «Список лиц» (мультивыбор из представления «лица_без_локальных», до 100 записей, обязательное). Остальные поля — служебные скрытые (data-internal, data-hidden).

8.1.2. Требования к правилам автоматизации

Правило 10249331 — Закрыть запрос если переоткрыли

Триггер: on status update — при изменении статуса записи.

Условие: was_completed and is_not_completed — запрос раньше был завершён и статус перестал быть «Завершено» (запрос переоткрыт).

  • action1: set member = member_was — возвращает участника запроса, который был назначен до завершения
  • action2: set status = completed — снова устанавливает статус «Завершено»
  • action3: set completion_reason = completion_reason_was — возвращает прежнюю причину завершения
  • action5: add note — добавляет комментарий для заявителя с пояснением об автоматизации

Правило 10249443 — Создать запрос в Р-Сервис. Заказ демо-стенда (ApiGate 1.0)

Триггер: on status update — при изменении статуса записи.

Условие: is_wf_pending and !was_wf_pending — запрос перешёл в статус «В рабочем процессе» (workflow_pending), а до изменения этим статусом не был.

Выражения: status = workflow_pending (is_wf_pending), status_was = workflow_pending (was_wf_pending), account.id (x4meaccount), find_all(person, custom_fields.emails).map(primary_email) (emails1), requested_by.name (ContactFIO) и другие — сбор данных для вебхука ApiGate.

Правило 13553013 — Завершить после решения от р-сервис

Триггер: on custom_fields update — при обновлении пользовательских полей записи.

Условие: note_vendor and request_vendor and !is_completed and note_was_updated — заметка от вендора заполнена, номер запроса вендора заполнен, запрос ещё не завершён, и обновление изменило заметку от вендора.

Выражения: custom_fields.note_rservice != null (note_vendor), custom_fields.request_rservice != null (request_vendor), status = completed (is_completed), custom_fields_was.note_rservice != custom_fields.note_rservice (note_was_updated).

Правило 1991869 — Автозавершение

Триггер: on status update — при изменении статуса записи.

Условие: no_failed_predecessors and no_registered_predecessors and (is_assigned or is_in_progress) — в рабочем процессе нет провалившихся задач, среди предшественников нет задач «Зарегистрировано», и задача мониторинга назначена либо в работе.

Выражения: status = assigned (is_assigned), status = in_progress (is_in_progress), predecessors.select(status = registered).size = 0 (no_registered_predecessors), workflow.tasks.select(status = failed).size = 0 (no_failed_predecessors).

Правило 13934321 — Сбой обработки

Триггер: after delay — запускается после задержки по времени.

Условие: is_assigned and is_robotic — задача по-прежнему назначена роботу (Служебная УЗ, id 3): ответ от вендора не поступил.

Выражения: status = assigned (is_assigned), member.id = 3 (is_robotic), workflow.requests[first].id (parent_req_id), workflow.requests[first].template.subject (parent_req_subj).

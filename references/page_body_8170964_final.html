Правило 10249331 - Закрыть запрос если переоткрыли

Триггер: on status update - при изменении статуса записи.

Условие: was_completed and is_not_completed - запрос раньше был завершён и статус перестал быть "Завершено" (запрос переоткрыт).

Выражения:

  • was_completed - `status_was = completed` — проверка, что до изменения запрос был в статусе «Завершено»
  • is_not_completed - `status != completed` — проверка, что после изменения статус не «Завершено» (запрос переоткрыли)

Действия:

  • action1: set member = member_was - Возвращает участника запроса, который был назначен до завершения
  • action2: set status = completed - Снова устанавливает статус «Завершено»
  • action3: set completion_reason = completion_reason_was - Возвращает прежнюю причину завершения
  • action5: add note '{{текст пояснения}}' - Добавляет комментарий для заявителя: выполнение запроса полностью автоматизировано, добавленные комментарии не учитываются, возобновление работ после возврата в работу закрытого запроса не производится, для нового обращения нужно зарегистрировать новый запрос по шаблону «МосИТСМ. Предоставление обучающих материалов» в услуге «МосИТСМ. Обучающие материалы»

Правило 1914157 - Генерация задачи на обработку

Триггер: on status update - при изменении статуса записи.

Выражения:

  • is_assigned - `status = assigned` — проверка, что задача мониторинга назначена
  • new_task - `new(task, "Обработка сбоев автоматизации (Автогенерация)")` — создание новой задачи по шаблону «Обработка сбоев автоматизации (Автогенерация)» (QA: шаблон 4315; при переносе на ПРОД поменять id)
  • all_failed_tasks - `workflow.tasks.select(status = failed)` — все провалившиеся задачи рабочего процесса
  • failed_task - `all_failed_tasks.select(status = failed)[last]` — последняя из провалившихся задач (событие сбоя)
  • this - `find(task, id)` — текущая задача мониторинга
  • phase - `failed_task.phase_name` — фаза сбойной задачи
  • failed_task_successors - `failed_task.successors.select(id != this.id)` — задачи-приёмники сбойной задачи, исключая саму задачу мониторинга
  • failed_name - `failed_task.subject` — тема сбойной задачи
  • failed_id - `failed_task.id` — номер сбойной задачи
  • fail_subject - `"Сбой в задаче " + failed_task + " (Автогенерация)"` — тема новой задачи об обработке сбоя
  • new_subject - `new_task.subject` — тема созданной задачи
  • new_id - `new_task.id` — номер созданной задачи
  • url - `account.url + "/tasks/"` — базовый адрес МосИТСМ для формирования ссылок на задачи
  • fail_instruction - `failed_task.instructions` — инструкции сбойной задачи (переносятся в новую задачу)
  • failed_last_comment - `failed_task.notes.select(medium != system)[last]` — последний не-системный комментарий сбойной задачи
  • comments_empty - `failed_task.notes.select(medium != system).size = 0` — проверка, что не-системных комментариев у сбойной задачи нет
  • fail_description - `comments_empty ? "..." : failed_last_comment.text` — комментарий для новой задачи: если комментариев нет — заглушка «Комментарий оставленный роботизацией был пустым, либо произошел сбой по времени ожидания», иначе текст последнего комментария
  • failed_present - `all_failed_tasks.size > 0` — проверка, что в рабочем процессе есть провалившиеся задачи

Действия:

  • action7: add note '{{текст}}' - Добавляет в задачу мониторинга комментарий о том, что для обработки сбоя задачи [{{failed_name}}]({{url}}{{failed_id}}) была сгенерирована новая задача
  • action8: update new_task add note '{{текст}}' - Добавляет в созданную задачу описание инцидента: произошёл сбой в автоматизированной задаче (ссылка), необходим ручной разбор инцидента, комментарий от роботизации {{fail_description}}
  • action11: update new_task set phase_name = phase - Устанавливает созданной задаче фазу сбойной задачи
  • action17: update new_task set subject = fail_subject - Устанавливает созданной задаче тему «Сбой в задаче … (Автогенерация)»
  • action19: update workflow add new_task to tasks - Добавляет созданную задачу в задачи рабочего процесса
  • action20: update new_task add failed_task_successors to successors - Назначает созданной задаче приёмников сбойной задачи (продолжение процесса после разбора сбоя)
  • action21: update new_task add failed_task to predecessors - Назначает сбойную задачу предшественником созданной задачи
  • action22: update new_task set instructions = fail_instruction - Копирует в созданную задачу инструкции сбойной задачи
  • action23: update all_failed_tasks set status = canceled - Отменяет все провалившиеся задачи рабочего процесса
  • action25: update all_failed_tasks add note '{{текст}}' - Добавляет в отменённые задачи комментарий о том, что для обработки сбоя была сгенерирована новая задача

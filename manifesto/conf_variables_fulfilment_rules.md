# Правила подстановки переменных в страницу Confluence

Версия: 1.2 (28.10.2026). Значения переменных запроса берутся из JSON-файла `request_vars_<id>_<дата-время>.json` — артефакт режима `request` скилла `mos_itsm_get_obj_structure`. Имя страницы — по правилам `page_name_creation_rule.md`. Изменения 1.2: `request.uri` подставляется как видимая гиперссылка «RFC {номер}».

| Переменная запроса | Переменная | Описание | Источник |
|---|---|---|---|
| `request.id` | `$req_id` | Номер запроса на изменение, в рамках которого создается страница с требованиями | пользователь → `request_vars_*.json` → `request.id` |
| `request.uri` | `$req_uri` | Ссылка на запрос `request.id` | `request_vars_*.json` → `request.uri` |
| `request.subject` | `$req_subject` | Заголовок запроса | `request_vars_*.json` → `request.subject` |
| `request.requested_for` | `$req_requested_for` | Для кого запрошено выполнение работ | `request_vars_*.json` → `request.requested_for` (имя + email) |
| `request.created_at` | `$req_created_at` | Дата и время создания запроса | `request_vars_*.json` → `request.created_at` |
| `request.notes[first]` | `$req_first_comment` | Первый комментарий из запроса (т.е. изначальная постановка запроса) | `request_vars_*.json` → `request.notes[first]` |

## Правила подстановки при создании страницы по шаблону 736854017

1. **Плейсхолдеры в теле шаблона** — поля `name="variableValues.req_*"` (в HTML-теле: `<input type="text" name="variableValues.req_id" ...>`). При подстановке **заменить весь `<input>`-элемент и его `<span class="templateparameter">(имя)</span>`** на текстовое значение переменной, сохранив стиль окружения.
2. **Имя страницы** строится по `page_name_creation_rule.md`: `{request.id}-{Название описываемого шаблона} - {краткое описание из шаблона}`; название шаблона взять из JSON структуры шаблона (`request_template.subject` / `req_template_subj`).
3. **Даты и время** — как в источнике (`request.created_at` в формате ISO из API); не переформатировать.
4. **Если переменная пуста** (например, `request.notes[first]` = «комментариев нет») — подставить «(не задано)» и перечислить такие переменные в итоговом отчёте. Если в текущей редакции шаблона плейсхолдер `req_uri`/`req_first_comment` отсутствует — `request.uri` идёт в добавляемую строку «Ссылка на запрос» (правило №7), `request.notes[first]` — в раздел 6.1 «Изначальная постановка» (вместо заглушки).
5. **`request.notes[first]`** — полный текст первого комментария (дата, автор, текст). Если он многострочный — вставить в Confluence как есть (переносы строк `<br/>`), не обрезая.
6. **Незаполненные переменные запроса** (`req_id`, `req_uri`, `req_subject`, `req_requested_for`, `req_created_at`, `req_first_comment`) — это норма только ДО того, как пользователь дал номер RFC; после получения `request_vars_*.json` все шесть должны быть заполнены.
7. **Поле «Ссылка на запрос» (раздел «Общие сведения», переменная `request.uri`)** — подставлять видимую гиперссылку формата:
   ```html
   <a href="{request.uri}">RFC {request.id}</a>
   ```
   Пример: `<a href="https://itsm.itsm-qa.mos.ru/requests/8170964">RFC 8170964</a>`. Текст ссылки — всегда «RFC {номер запроса}», адрес — значение `request.uri` из `request_vars_*.json`.
   Плейсхолдер строки — `<img ... template-variable?name=req_uri ...>` (переменная `req_uri`). Если в текущей редакции шаблона строки «Ссылка на запрос» нет — добавить её в таблицу раздела «Общие сведения» после строки «Запрос» (стиль ячеек как у соседних).
8. **Раздел «Оглавление» НЕ изменять**: оглавление формируется автоматически штатным макросом Confluence «Оглавление» (TOC-макрос; в теле шаблона выглядит как отрендеренный блок `toc-macro`). Не редактировать его содержимое, не удалять, не дописывать пункты вручную — он перестроится сам после публикации страницы.

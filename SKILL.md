# ITPM Wiki REQ Page Creator

Скилл создаёт в Confluence страницу требований по корпоративному шаблону: получает тело шаблона, заполняет места для подстановки значениями от пользователя и публикует страницу через REST API.

Сервер — Confluence Data Center в корне домена (REST без префикса `/wiki`). Все шаги ниже проверены на реальном сервере; не заменяй их другими эндпоинтами без необходимости.

## Шаг 1 — Проверка доступов в Confluence и ITSM

Параметры лежат в `.env` рядом с SKILL.md:

- `CONFLUENCE_BASE_URL` — базовая ссылка
- `CONFLUENCE_API_TOKEN` — персональный токен доступа (PAT) как есть, без base64
- `ITPM_TEMPLATE_ID` — ID шаблона REQ
- `ITPM_SPACE_KEY` — пространство шаблона
- `ITPM_PARENT_PAGE_ID` (необязательно) — родительская страница по умолчанию

```bash
cd "<папка скилла>"
BASE=$(python -c "import json;print(json.load(open('skill_env.json',encoding='utf-8-sig'))['CONFLUENCE_BASE_URL'].rstrip('/'))")
TOKEN=$(python -c "import json;print(json.load(open('skill_env.json',encoding='utf-8-sig'))['CONFLUENCE_API_TOKEN'])")
AUTH="Authorization: Bearer $TOKEN"
curl -sS -m 15 -H "$AUTH" "$BASE/rest/api/user/current"
```

**Обязательно проверь авторизацию.** Если в ответе `"type": "anonymous"` — токен не принят; остановись и попроси перевыпустить токен (аватар → Настройки → Персональные токены доступа) и вставить его в `skill_env.json` как есть. Этот сервер при неверном токене не возвращает 401, а молча отвечает как аноним — без этой проверки всё выглядит «почти работающим».

## Шаг 2 — Собери параметры страницы

- **title** — заголовок новой страницы (из запроса пользователя).
- **space key** — где создать страницу; из запроса, иначе спроси. (Пространство `DIT4ME` — это источник шаблона, страницу туда класть не обязательно.)
- **parent page ID** — из запроса, иначе `ITPM_PARENT_PAGE_ID`, иначе без родителя.
- **значения для заполнения** — лучше одним JSON-объектом. Если каких-то значений не хватает, задай недостающие вопросы одним сообщением, а не по одному.

Не задавай вопросов, если всё уже есть в запросе или в `skill_env.json` или в файле `.env`.

## Шаг 3 — Получи актуальный шаблон-трафарет для заполнения

REST-эндпоинты шаблонов (`/rest/api/template/...`) на сервере отключены — не используй их. Тело шаблона извлекается из страницы-просмотра готовым скриптом:

```bash
cd "<папка скилла>"
python scripts/fetch_template.py
```

Скрипт читает `ITPM_TEMPLATE_ID` и `ITPM_SPACE_KEY` из `skill_env.json` (можно передать и аргументами), скачивает `pages/templates2/viewpagetemplate.action`, извлекает сбалансированный блок `wiki-content view-template` и сохраняет его в `template_body.html`. В stdout он печатает список мест для заполнения.

## Шаг 4 — Подготовь страницу к созданию

Места для заполнения в шаблоне — это макросы Placeholder, в HTML они выглядят так:

```html
<span class="template-variable">`{{переменная}}`</span>
```
Замена: для каждой переменной подставь значение пользователя. Пример замены одного места:
Правила подстановки - СТРОГО из файла `manifesto/conf_variables_fulfilment_rules.md`

Значения для переменных получишь в результате применения скиллов:
- mos_itsm_automation_rule_descriptor
- mos-itsm-get-obj-structure
- mos-itsm-ui-extension_descriptor

Правила:

- Текст пользователя вставляй валидным XHTML: экранируй `&`, `<`, `>`; переносы строк оформляй абзацами `<p>...</p>`.
- **Поле «Ссылка на запрос»** (раздел «Общие сведения», переменная `request.uri`): подставлять видимую гиперссылку `<a href="{request.uri}">RFC {request.id}</a>` — например `<a href="https://itsm.itsm-qa.mos.ru/requests/8170964">RFC 8170964</a>`. Не использовать голый `<ac:link>` без текста и не дописывать URL текстом рядом со ссылкой.
- **Раздел «Оглавление» не изменять**: он формируется автоматически штатным макросом Confluence «Оглавление» (TOC). Не редактировать, не удалять, не дописывать пункты вручную — макрос перестроит список сам после публикации.
- **Раздел 8.2 «Шаблон Рабочего процесса»** — по каждому найденному в структуре шаблону задачи формируется самостоятельный подраздел. Если в РП три задачи, в разделе 8.2 должно быть три подраздела:
  - `Шаблон задачи [Название шаблона задачи 1]`
  - `Шаблон задачи [Название шаблона задачи 2]`
  - `Шаблон задачи [Название шаблона задачи 3]`

  Внутри каждого подраздела — свои подпункты (заголовками на уровень ниже):
  - `Требования к Расширению UI [номер] [имя]` — если у задачи есть расширение UI; иначе «Отсутствует»;
  - `Требования к правилу автоматизации [номер] - [имя]` — по каждому правилу задачи, с кратким описанием и ссылкой на карточку; если правил нет — «Отсутствуют».

  Порядок задач — как в структуре РП (по фазам). Статический плейсхолдер шаблона `8.3 «Шаблон задачи»` с `task_template_name` при этом заменяется первым подразделом «Шаблон задачи [...]» — дублирующий общий заголовок не оставлять.
- Внешние ссылки (кроме «Ссылка на запрос») вставляй только как `<ac:link><ri:url ri:value="URL" /><ac:plain-text-body>Текст ссылки</ac:plain-text-body></ac:link>` — у `ac:link` **обязателен непустой текст** (`<ac:plain-text-body>`), иначе Confluence рендерит «Поврежденная ссылка» (ошибка из прогона 28.10.2026: столбец «Ссылка на карточку» в 8.1.2). Голый `<a href="URL">` в остальных местах вызывает HTTP 500 (ClassCastException на ResourceIdentifier). После публикации проверяй ссылки (Шаг 6).
- **Описания правил автоматизации на странице** переноси со структурой из SKILL скилла `mos_itsm_automation_rule_descriptor` (`references/description_template.md`): секции «Настройки правила» (триггер, условие), «Выражения» (имя + логика), «Действия» (действие + описание) — в виде тех же построчных HTML-таблиц; «Описание» и «История изменений» правила целиком не дублировать. Если текст описания уже сгенерирован этим скиллом (файл `desc_<id>.md`) — используй его как источник, а не пересказывай правило заново.
- Автор требования вставляется **@-упоминанием пользователя**, а не макросом: `<ac:link><ac:link-body><ri:user ri:userkey="USERKEY" /></ac:link-body></ac:link>` — рендерится как «@Имя» и «упоминает» пользователя. Userkey — голый `<ri:user ri:userkey=...>` (через `/rest/api/user/current` для себя или `/rest/api/user?username=...` для другого); строка username в параметре даёт HTTP 500. Если userkey получить нельзя — оставь плейсхолдер и отметь в итоге. Макрос `profile` для «Автор»/«Автор требования» **не использовать** (корректировка 28.10.2026).
- Незаполненные места не выдумывай: сохрани их как есть и перечисли пользователю в итоге.
- **Нумерация подразделов — по стилю страницы.** Все разделы и подразделы шаблона пронумерованы (`1.`, `8.1.`, `8.1.1.` — span `numhead-number`). Новые подразделы («Шаблон задачи N», «Требования к Расширению UI N N», «Требования к правилу автоматизации N - N») продолжают нумерацию родительского раздела: подразделы задач — следующий номер после статического плейсхолдера (например `8.2.1.`, `8.2.2.`…), вложенные — по глубине (`8.2.1.1.`, `8.2.1.2.`…). Формат — как у соседних заголовков: `<h2 id="..."><span class="numhead-number">8.2.1. </span>Шаблон задачи ...</h2>`. Не оставляй новые подразделы без номера, если нумерация есть на всей странице.
- **Ссылки на карточки МосИТСМ** (правила автоматизации, расширения UI, шаблоны задач/РП) — `<ac:link><ri:url ri:value="..." /><ac:plain-text-body>Карточка правила 10249331</ac:plain-text-body></ac:link>` (текст ссылки обязателен).

## Шаг 5 — Создай страницу

Только v1 API (`POST /rest/api/content`); v2 на сервере недоступен:

```bash
python - <<'EOF'
import json, os
payload = {
    "type": "page",
    "title": os.environ["PAGE_TITLE"],
    "space": {"key": os.environ["SPACE_KEY"]},
    "body": {"storage": {"value": open("page_body.html", encoding="utf-8").read(),
                          "representation": "storage"}},
}
if os.environ.get("PARENT_ID"):
    payload["ancestors"] = [{"id": os.environ["PARENT_ID"]}]
open("payload.json", "w", encoding="utf-8").write(json.dumps(payload))
EOF
PAGE_TITLE="..." SPACE_KEY="..." PARENT_ID="..." python - <<'EOF'
import json, urllib.request, os
env = json.load(open("skill_env.json", encoding="utf-8-sig"))
base = env["CONFLUENCE_BASE_URL"].rstrip("/")
req = urllib.request.Request(base + "/rest/api/content",
    data=open("payload.json","rb").read(),
    headers={"Authorization": "Bearer " + env["CONFLUENCE_API_TOKEN"],
             "Content-Type": "application/json"}, method="POST")
resp = json.loads(urllib.request.urlopen(req, timeout=30).read())
print(resp["id"], resp["_links"]["base"] + resp["_links"]["webui"])
EOF
```

Проверь ответ: HTTP 200 содержит `id` и `_links.webui`. 403 или «permissionViolation» — у токена нет прав на запись в это пространство: сообщи пользователю, не повторяй запрос.

## Шаг 6 — Проверь страницу и верни результат

**После публикации проверь сформированные ссылки.** Скачай тело страницы (`GET /rest/api/content/<id>?expand=body.storage`) и сверь каждую вставленную `<ac:link><ri:url ...>`: рядом должен быть непустой `<ac:plain-text-body>` с текстом ссылки. Пустой `ac:link` (без текста) рендерится как «Поврежденная ссылка» — при обнаружении исправь тело (`PUT` новой версией страницы) и повтори проверку. Также проверь нумерацию заголовков (`numhead-number`) и «Автор» (@-упоминание с непустым текстом).

Сообщи пользователю: ссылку на страницу (из `_links.base` + `_links.webui`), заголовок, ID, результат проверки ссылок и список незаполненных мест в шаблоне (если остались). При ошибке — точный текст ответа сервера и что исправить.
